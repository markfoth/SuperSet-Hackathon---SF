## Exact local commands

PowerShell in this repository (use `npm.cmd` if execution policy blocks `npm.ps1`):

```powershell
npm.cmd ci
npm.cmd run dev -- --host localhost --port 5188 --strictPort
```

Open `http://localhost:5188`. Port 5173 was already serving an older checkout during this
session; that unrelated server was left untouched. Owned verification servers are stopped
after verification; restart using these commands.

Production build and local preview:

```powershell
npm.cmd run build
npm.cmd run preview -- --host localhost --port 4173 --strictPort
```

Open `http://localhost:4173`. `dist/` is the production artifact. No hosting service is required
for this local handoff. Vite's development `/api` routing proxy does not transfer into a static
production artifact; live routing under future hosting needs a server-side proxy URL.

Tests:

```powershell
npm.cmd test
npm.cmd run test:proxy
npm.cmd run test:browser
.venv/Scripts/python.exe -X utf8 -m pytest
.venv/Scripts/python.exe -X utf8 scripts/validate_datasets.py
```

Rebuild from the cached original sources:

```powershell
.venv/Scripts/python.exe -X utf8 scripts/rebuild_all.py --offline --dataset hills cycling
```

A fresh Python setup needs `python -m venv .venv` and
`.venv/Scripts/python.exe -m pip install -r requirements.txt`. A fresh raw-data setup needs
`scripts/rebuild_all.py` without `--offline`. Processed data and photos are committed, so
ordinary frontend development never needs Python or raw downloads.

## Remaining limitations and external input

- **Live-provider validation pending:** user offered to add `TRAVELTIME_APP_ID` and
  `TRAVELTIME_API_KEY` to gitignored `.env`; no keys were available during verification.
  The server/client path and HTTP failure handling are tested, but no genuine TravelTime
  polygon has been claimed as verified. After adding keys, run `npm.cmd run proxy`; in another
  PowerShell terminal set `$env:VITE_COMMUTE_PROVIDER='proxy'` and
  `$env:VITE_ROUTING_PROXY_URL='/api'`, then start development. Check `/health` and verify the
  workplace label says TravelTime rather than the disclosed fixture fallback.
- Offline transit uses the documented GTFS approximation and expired Muni timetable; other
  offline modes remain explicitly **Synthetic**. Custom workplaces block when neither routing
  nor a supported fixture is available.
- DEM-derived street grades are not surveyed and can misrepresent bridges, tunnels and
  retaining walls. The cell median does not promise every street is flat; p90 and >10% street
  share are available. 1,013 cells have sufficient street coverage; others retain nulls.
- Access distances use straight lines, without entrance, crossing, barrier or routing models.
  Residential evidence is conservative and incomplete; no parcel-use inventory was added.
- Crime is shared H3-8 context, pollution is tract context, and rents are historical ZIP-level
  asking indices. They are not independently measured per H3-9 cell. Source ids and limitations
  remain available in cell details, canonical metadata and the manifest.
- Existing unresolved data redistribution terms and basemap hosting requirements still apply
  before any future public deployment; no such deployment is part of this handoff.
